# Drax Residual-Delta Fusion Notes

## Overview

Drax is a project-specific hybrid feature-mixing block. In the current implementation, it combines a ConvNeXt-style local branch with an optional self-attention global branch.

Conceptually:

```text
f1 = ConvNeXtBlock(x) - x
f2 = SelfAttention2D(x) - x
fusion = 0.5 * (f1 + f2)
output = x + fusion
```

The subtraction extracts the residual update from each branch. Since both branches already behave like residual modules, subtracting `x` avoids mixing the original feature tensor multiple times. The block keeps the original feature `x`, combines only the proposed changes from each branch, then adds the fused update back.

In efficient attention mode, the attention branch is computed in a reduced channel space:

```text
reduced = attn_down(x)
f2 = attn_up(SelfAttention2D(reduced) - reduced)
```

The core intuition is:

- the ConvNeXt branch proposes a local-detail correction
- the self-attention branch proposes a global-context correction
- Drax fuses both corrections and applies them as a residual update

In this repository, Drax is used in two main image-classification paths:

- `draxnet`: a ResNet-18-style model where the default stage layout is `basic,basic,basic,drax`, meaning the final stage uses `DraxResidualBlock`
- `drax_mobilenet_v3_large`: a MobileNetV3 Large backbone with a bottlenecked late-stage `DraxBlock` refiner

Object detection also exposes `draxnet-yolo26`, but that model YAML is expected from the `ralampay/ultralytics` fork rather than being defined directly in this repository.

## Similar Approaches

The broad idea is not entirely new. Drax is best understood as a specific instance of residual feature learning and multi-branch feature fusion.

Relevant research families:

| Category | Paper | Venue/Year | Relevance to Drax | Link |
| --- | --- | --- | --- | --- |
| Residual learning | He et al., "Deep Residual Learning for Image Recognition" | CVPR 2016 | Reformulates a block as learning `F(x) = H(x) - x`, then outputs `x + F(x)`. Drax explicitly extracts branch residuals in a similar spirit. | https://arxiv.org/abs/1512.03385 |
| Residual prediction in image restoration | Zhang et al., "Beyond a Gaussian Denoiser: Residual Learning of Deep CNN for Image Denoising" | TIP 2017 | Predicts the residual/noise component instead of the full clean output. This is closely related to learning "what remains" or "what should be corrected." | https://arxiv.org/abs/1608.03981 |
| Residual prediction in super-resolution | Zhang et al., "Image Super-Resolution Using Very Deep Residual Channel Attention Networks" | ECCV 2018 | Uses residual-in-residual structure and attention to focus model capacity on harder residual detail. | https://arxiv.org/abs/1807.02758 |
| Aggregated residual transformations | Xie et al., "Aggregated Residual Transformations for Deep Neural Networks" | CVPR 2017 | Aggregates multiple residual branches before adding them back to the input, similar to Drax's multi-branch residual-update framing. | https://arxiv.org/abs/1611.05431 |
| Adaptive branch fusion | Li et al., "Selective Kernel Networks" | CVPR 2019 | Dynamically weights multiple branches, usually with different receptive fields. This is relevant to replacing Drax's fixed `0.5` average with learned/adaptive branch weights. | https://arxiv.org/abs/1903.06586 |
| Attention-based feature fusion | Dai et al., "Attentional Feature Fusion" | WACV 2021 | Studies feature fusion directly and argues that simple addition or concatenation is often too limited. | https://arxiv.org/abs/2009.14082 |
| Channel recalibration | Hu et al., "Squeeze-and-Excitation Networks" | CVPR 2018 | Learns channel-wise weights to modulate features, related to weighted branch or feature fusion. | https://arxiv.org/abs/1709.01507 |

The likely novelty is not residual subtraction itself. A more defensible framing is:

```text
A lightweight late-stage hybrid residual-delta fusion block combining ConvNeXt-style local mixing and efficient 2D self-attention.
```

## Gaps Identified

The current Drax fusion is fixed:

```text
fusion = 0.5 * (conv_delta + attention_delta)
```

This creates several research gaps:

- **Static fusion may be too crude**: equal weighting assumes the convolution and attention deltas are equally useful for every input, class, layer, and spatial region.

- **Delta magnitudes may not be calibrated**: `conv_delta` and `attention_delta` may have different scales or noise profiles, so direct averaging can let one branch dominate.

- **Branch complementarity is not guaranteed**: the two branches may learn redundant updates. Measuring similarity between deltas would help determine whether the branches contribute distinct information.

- **Semantic alignment is assumed**: addition assumes both deltas are compatible feature-wise. Even tensors with the same shape may encode different types of information.

- **Placement is not fully studied**: Drax is currently used late in the network by default, but the best stage placement should be tested through ablations.

- **Attention cost-benefit tradeoff needs evidence**: efficient attention reduces cost, but it should still be compared against other ways to increase receptive field, such as larger kernels, dilated convolutions, or dynamic convolutional branches.

Useful ablations:

```text
conv_delta only
attention_delta only
fixed average fusion
learned scalar fusion
channel-wise fusion
spatial fusion
stage placement: layer2, layer3, layer4, layer3+layer4
```

## Proposed Modification for Weighted Feature Fusion

Replace the fixed average:

```text
fusion = 0.5 * (f1 + f2)
output = x + fusion
```

with weighted residual-delta fusion:

```text
fusion = f1 * w1 + f2 * w2
output = x + fusion
```

where:

```text
f1 = ConvNeXtBlock(x) - x
f2 = SelfAttention2D(x) - x
```

Literature categories for this modification:

- weighted feature fusion
- learnable weighted fusion
- adaptive feature fusion
- attention-based feature fusion
- gated feature fusion
- dynamic feature fusion
- weighted residual feature fusion

Possible versions:

- **Fixed scalar weights**: manually set `w1` and `w2`, such as `0.7` and `0.3`
- **Learned scalar weights**: trainable global weights shared across all inputs
- **Input-adaptive weights**: a small gating network predicts `w1` and `w2` from `x`
- **Channel-wise weights**: each channel receives different branch weights
- **Spatial weights**: each spatial location receives different branch weights
- **Spatial-channel weights**: the most expressive option, but also the most expensive

A concise research framing:

```text
Residual-delta extraction with adaptive branch weighting between local convolutional and global attention updates.
```

The key question is whether the model can learn when to trust local convolutional corrections more and when to trust global attention corrections more, instead of always averaging them equally.
